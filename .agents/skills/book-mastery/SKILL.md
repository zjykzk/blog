# book-mastery：用表现证据判断是否掌握一本书

“读完”“看懂”“能认出书里的话”都不是掌握证据。掌握意味着：离开原文后仍能重建书的核心结构，说明关键结论为何成立，把它迁移到未见过的情境，并知道它在哪里失效。

```text
熟悉 ≠ 回忆 ≠ 理解 ≠ 迁移 ≠ 稳固掌握
```

测试不是把人难倒，也不是重新讲一遍书。它要找出学习者已经能独立完成什么、还需要提示什么，以及知识在哪个边界上失灵。

## Workflow Routing

| 用户状态 | 行动 |
|---|---|
| 提供原书、PDF、EPUB 或可靠全文 | 以原文建立隐藏的掌握蓝图，开始测试 |
| 提供 `ljg-book` 成品及 coverage | 以成品覆盖范围建立蓝图，明确这是对该成品所覆盖内容的测试 |
| 只给书名 | 先在用户指定目录和 `~/Context/` 搜索匹配的 `__book.md` 与 coverage；找不到可靠材料时，只问一个问题，请用户提供材料或允许检索 |
| 提供自己的读书笔记 | 可以测试笔记中体现的理解，但不能宣称已经验证整本书掌握度 |
| 恢复上次测试 | 从 `wiki/sources/books/` 读取最近的 `__mastery.md`，优先测试到期项目和上次薄弱点 |
| 用户说停止、先到这里 | 立即给部分结论并保存，明确尚未覆盖的部分 |

如果书名、版本和材料都明确，不要再用问卷拖延。默认目标是“整本书的可迁移掌握”，默认不允许测试时查看原书或笔记。

## 1. 建立隐藏的掌握蓝图

先读可用材料，再读 `references/rubric.md`。不要把蓝图提前展示给学习者，避免把测试变成照着答案复述。

蓝图只保留真正承重的内容：

- 全书试图回答的核心问题；
- 5–9 个不可缺少的概念、人物、模型或变化节点；
- 它们之间最重要的因果、依赖、对照或时间关系；
- 至少一个适用边界、反例或证据限制；
- 能检验迁移的两个陌生情境；
- 对这本书而言，哪些细节必须准确，哪些不值得考记忆。

根据书型调整蓝图：

- 论证/方法书：主张、前提、推理链、反例、应用边界；
- 历史/传记：关键时序、行动者、约束、因果与证据/解释边界；
- 文学：人物关系、关键变化、形式如何产生意义、无法消除的歧义；
- 技术/科学：模型、机制、预测、操作或计算、失效条件。

## 2. 标明证据边界

开始前用一句话说明此次判断基于什么：原书、完整拆书成品、用户笔记或混合材料。

证据上限：

- 原书或足够完整的原始材料：可以判断本次抽样范围内的整书掌握；
- 通过验证的 `ljg-book` 成品与 coverage：可以判断该成品所覆盖的全书结构；
- 用户笔记或摘要：只能判断笔记范围内的理解；
- 只有书名或模型记忆：不能给出可靠的全书掌握结论。

不要把没有覆盖到的章节算作“通过”，也不要凭自己对名著的记忆补写隐藏答案。

## 3. 无提示基线

第一问让学习者离开原文，用自己的话重建：

> 这本书最想解决什么问题？作者最后给出了什么回答？中间靠哪几步走到那里？

一次只问一个承重问题，然后停下来等待回答。不要先给选项、关键词、章节名或答案轮廓。

学习者若请求提示，可以给一个逐级缩小的提示，但该知识点标记为“提示后完成”，不能算作独立掌握。

## 4. 自适应追问

依据回答暴露出的模型选择下一问，不按固定题库排班。测试必须覆盖五种证据：

1. **准确重建**：关键事实、概念或主张没有实质错误；
2. **结构解释**：能说明为什么、怎样发生，各部分如何连接；
3. **概念辨析**：能与相邻概念、表面相似情境或常见误读区分；
4. **陌生迁移**：能在书中没有直接出现的新情境中使用；
5. **边界与修正**：能指出失效条件，并在反证出现时修改原判断。

追问规则：

- 先让用户回答，再反馈；不要把答案藏在问题里。
- 答案正确但理由错误，不算通过。
- 复述术语却无法说明关系，只算识别或记忆。
- 举出书中原例，只证明记忆；至少再测一个陌生情境。
- 被提醒后答对，记录为“本次学会”，不能倒算为“测试前已掌握”。
- 发现一个具体缺口时，缩窄问题让用户再试一次；仍不会再解释，不连续拷问。
- 对价值型作品，反例只能检验预测、代价与一致性，不能把一种价值权重强判为唯一答案。

通常使用 8–12 个问题。只有在所有承重节点至少被抽样一次、完成两个陌生迁移并测试一个边界后，才能给整书结论。材料不足或用户提前停止时，给部分结论。

## 5. 判定掌握层级

按 `references/rubric.md` 记录五维证据。不要只报总分，也不要用流畅表达替代内容证据。

- **尚未形成可检验理解**：核心问题或主要结构无法独立重建；
- **可复述**：能回忆主要结论，但解释、辨析或迁移明显依赖提示；
- **结构性理解**：能独立重建核心结构，知道主要因果与边界，但迁移仍不稳定；
- **可迁移掌握**：能在至少两个陌生情境中正确使用，并能处理反例和相邻概念；
- **稳固掌握**：达到可迁移掌握，并在至少 24 小时后的无提示复测中保持。

一次会话最多判到“可迁移掌握”。没有延迟复测，不得写“稳固掌握”。

## 6. 反馈而不是公布答案

每轮反馈只做三件事：

1. 指出已得到的证据；
2. 点出一个最关键的缺口；
3. 给下一道能区分“会复述”和“会使用”的问题。

完整解释留到该知识点完成一次回答和一次重试之后。解释完成后，把它标记为“测试中补学”，并安排后续重测。

不要用“你理解得很好”代替证据。应说清楚：“你独立重建了 A→B→C，但在条件 D 改变后仍沿用原规则，因此结构理解通过，迁移尚未通过。”

## 7. 保存掌握记录

读 `references/report-template.md`，将每次测试保存到当前知识库的书籍来源目录：

```text
wiki/sources/books/{YYYYMMDDTHHMMSS}--掌握-{书名关键词}__mastery.md
```

使用 `date +%Y%m%dT%H%M%S` 生成时间戳，并在目录不存在时创建 `wiki/sources/books/`。记录每次问题、用户回答的证据摘要、是否使用提示、暴露的缺口、补学内容和下次复测时间。不要只保存最终总分；学习过程本身是以后判断进步的依据。

默认复测间隔：首次通过后 1 天、3 天、7 天、14 天、30 天。失败项目回到 1 天；用户指定节奏时以用户为准。

保存后报告文件路径。掌握记录虽然保存在 wiki 内，但属于书籍学习证据；默认不自动更新 `index.md`、`log.md` 或 `hot.md`，避免每轮复测淹没稳定知识入口。

## 8. 收束格式

最终只给证据化结论：

```markdown
## 判定
<层级> — <一句话说明证据边界>

## 已经掌握
- <能独立完成的具体任务 + 对应证据>

## 尚未掌握
- <具体缺口，不写人格评价>

## 本次补学
- <测试过程中才获得的内容；没有则省略>

## 下一次复测
- <日期与只测哪些薄弱点>
```

## Boundaries

- 不负责第一次讲完整本书；先用 `ljg-book`。
- 不把 `ljg-qa` 生成的问答直接当试卷；它是作者论证地图，会泄露答案结构。
- 可以借用 `ljg-teach` 的陌生情境与迁移思想，但本技能必须覆盖整书蓝图并给出掌握判定。
- 不以章节细节记忆量、阅读时长、划线数量或自信程度判断掌握。
- 不在证据不足时给“整本书已掌握”的结论。
