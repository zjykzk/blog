# Harness² 算法执行过程演示 · 旁白稿

> 来源：Harness²: Recursive Agent Harnessing for an Open World，arXiv:2610.14224v1。

## 0:00 同一个模型，换一套工作套件

同一个模型，换一套工作套件，表现可能差很多。
Harness² 研究的是：在没有标准答案的新任务上，怎样边做边改这套工作套件。

## 0:11 什么是 harness

Harness 是包在模型外面的整套工作环境：指令、手册、记忆、脚本、工具设置、子代理和检查钩子。
整个算法里，模型参数不变，被修改的只有这套 harness。

## 0:25 第 0 步　参考运行

来看论文里的一个任务：根据日程、人员、场地和预算，整理一组制片交付物。
第零步，用原始 harness 完整做一遍，留下参考轨迹。
轨迹暴露了两个问题：几份文件之间的数字没有核对，写完以后也没有复查。
注意，参考轨迹只说明它怎么做，不说明做得对不对。

## 0:47 第 1 步　提出（Propose）

第一步，提出。两位编辑者从不同方向，各写一份候选 harness。
通用编辑者处理跨行业的做事习惯：先清点所有输入，结束前用脚本重新打开每份产出。
领域编辑者处理当前行业：加入预算核对手册，并提醒表格里的金额要先去掉符号和逗号再计算。

## 1:09 第 2 步　试跑（Probe）

第二步，试跑。每份候选都在同一任务、同一模型、同一环境里重新执行。
把候选轨迹和参考轨迹并排比较：原来的问题有没有消失，有没有带来新的问题。
这里判断的是行为变化，不是答案对错。

## 1:26 第 3 步　组合（Compose）

第三步，组合。组合者阅读全部轨迹，只保留有行为对比支持的修改。
每一处采用都要对应一条具体观察；没有证据支持的修改，直接舍弃。
这一例中，四处修改都留了下来。新 harness 再运行，核对了数字，也补齐了备忘录。

## 1:46 优化时看不到分数

整个改进过程中，编辑者、组合者和挑选者都看不到评分标准和分数。
论文只在事后用评分器衡量：这份产出从 43.1 分升到 77.8 分。
另一组实验里，较弱的 GLM-5 改进后从 64.2 升到 75.7，超过了较强模型用原 harness 的 72.4。

## 2:09 第 4 步　扩展预算与选择

预算更多时，可以并行写出 k 组候选，也可以顺序连续改 k 轮。
两种方式都会得到几份结果，由挑选者在不知道来源的情况下，对照任务要求选出一份。
什么时候停下？论文按预先设定的预算停止，而不是等到证明结果正确。

## 2:28 第 5 步　沉淀经验（第二层递归）

任务结束后，反思者回看整个改进记录，只提炼有试跑证据支持的经验。
经验库保存采用的 harness、可运行脚本、适用情形和支持证据。
下一项任务仍然从原始 harness 出发，只在提出和组合修改时查阅经验库，再用新的试跑确认是否有用。

## 2:48 边界：行为变化 ≠ 结果正确

但是，行为变化不等于结果正确。
一项代码任务里，五份结果事后得分是 95、85、85、80 和 55，挑选者却选了 55 分那份。
如果几份候选共享同一个错误假设，它们会犯同样的错，对比也照不出来。

## 3:07 两层循环

总结一下：任务内，用同条件试跑筛选修改；任务间，把有证据的经验交给下一项任务。
它让 harness 的改进有据可查，但真正的正确性，仍然需要独立验证和真实反馈。
