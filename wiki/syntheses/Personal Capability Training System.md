# Personal Capability Training System

## Context

AI 让搜索、生成和标准执行迅速变便宜以后，人的稀缺价值更多地转向目标选择、质量判断、现实验证、关系协作和责任承担。单独追踪阅读、运动、专注、人脉或提示词技巧，容易产生大量局部优化，却不能保证这些活动共同转化为现实能力。

需要训练的不是一组彼此独立的美德，而是一套能长期运行的个人系统：它把有限精力持续转化为更好的判断、真实成果、可信关系和可复用资产。

## Finding

个人能力训练应以一个真实项目为核心，而不是以习惯清单为核心。每个周期只保留一个主项目，让同一项现实任务同时训练主体性、判断力、人机协作、执行、学习、审美、关系与资产化。

系统由四个关键变量支撑：

| 变量 | 系统作用 | 失效表现 |
| --- | --- | --- |
| 身体能量 | 提供稳定输入 | 疲惫、冲动、注意力破碎 |
| 注意力配置 | 决定能量流向哪个目标 | 被信息流和次要任务持续劫持 |
| 现实反馈 | 校准判断和行动 | 在自洽叙事里反复强化错误 |
| 资产沉淀 | 让一次劳动降低未来成本 | 每轮都从零开始，只出售当下时间 |

它们形成一条主闭环：

```text
身体供能
  ↓
自主选择真实项目
  ↓
配置注意力与人机分工
  ↓
交付可被现实检验的成果
  ↓
获取使用、协作与结果反馈
  ↓
修正判断、流程与项目方向
  ↓
沉淀知识、工具、信誉与关系资产
  └──────────────────→ 下一轮选择能力提高
```

这条结构把 [[wiki/concepts/Human Agency|人的能动性]] 从态度变成运行机制，也把 [[wiki/concepts/Cognitive Engineering|认知工程]] 从信息管理落实为“人、AI、工具、反馈”共同参与的行动系统。

## Project Selection Gate

主项目必须同时通过以下检查：

- **真实价值**：它为某个具体的人或群体解决问题，而不只是制造练习记录。
- **真实不确定性**：不能照教程完整复制，必须进行取舍与判断。
- **人机协作**：AI 可以提高效率，但目标、标准、风险和责任不能完全外包。
- **可检验交付**：周期内能够产生可展示、可使用或可测试的成果。
- **外部反馈**：至少有一位真实使用者、协作者或评审者能够反馈。
- **资产潜力**：过程能够留下模板、工具、知识、作品、流程或信誉。

如果一个项目没有外部使用者和可检验结果，它更像封闭练习；如果没有不确定性，它只能训练熟练度；如果没有沉淀，它通常只是一次性劳动。

## Operating Loop

### 选择：训练主体性

启动时写一页决策说明：

- 要产生什么现实结果？
- 为什么现在值得做？
- 明确放弃哪些竞争目标？
- 最大的不确定性是什么？
- 什么证据会触发转向或停止？

主体性不是固执坚持，而是主动选择、保留修正权并承担选择成本。

### 分工：训练人机协作

把任务分为三类：

| 责任位置 | 典型内容 |
| --- | --- |
| 人决定 | 目标、价值排序、验收标准、风险边界、最终责任 |
| AI 执行 | 搜索、整理、生成候选、格式转换、重复操作 |
| 人机共同完成 | 推演、反驳、比较、修改、验证和异常处理 |

AI 的输出应包含备选方案、关键假设、证据来源和可能错误。这样可以扩大认知带宽，而不把问题意识和判断责任一起外包。

### 验证：训练判断力

重要结论至少接受四项检查：

- 原始信息和独立证据来自哪里？
- 哪个假设最脆弱？
- 什么反例能推翻当前判断？
- 真实使用者是否得到预期结果？

关键预测应在行动前记录概率和判断依据，事后核对结果。判断力因此表现为预测与现实之间的持续校准，而不是事后解释能力。对高频判定，可以把规则、反例和检查表沉淀为 [[wiki/concepts/Judgment Externalization|判定外化]] 资产。

### 交付：训练执行与审美

每周必须产生一个可被别人检查的版本，而不是只积累素材。审美通过“比较、说明、删改、观察”训练：比较多个候选，说明评价标准，删除不服务目标的部分，再观察真实受众的反应。

审美在这里不是个人偏好的同义词，而是识别什么形式最适合目标、对象和约束的能力。

### 反馈：训练快速学习

每次交付后只回答四个问题：

- 原本预期什么？
- 实际发生什么？
- 差异由什么机制产生？
- 下一轮只改变哪个关键变量？

结果必须改变下一轮行动，才构成真正的 [[wiki/concepts/Feedback Loops|反馈回路]]。快速学习不是吸收信息更快，而是缩短行动、暴露误差和完成修正之间的延迟。

### 沉淀：建立复利资产

每轮至少留下一个可复用对象：

- 决策规则或检查清单
- 模板、流程或自动化工具
- 结构化知识或评测样本
- 公开作品或可信履历
- 可重复提供的服务
- 经共同交付验证的合作关系

资产是否复利，不看它是否被保存，而看它以后是否被再次调用，并降低行动成本或提高结果质量。

### 协作：建立真实关系

关系不以扩大联系人数量为目标，而以共同解决问题为载体：发现具体需求，做出清晰承诺，按时交付，接受批评并完成修改。高信任来自可验证的共同经历和长期兑现，而不是互动频率本身。

## Operating Rhythm

| 周期 | 核心动作 | 必须留下的证据 |
| --- | --- | --- |
| 每日 | 守住身体底线，完成主项目深度工作 | 可检查的进展或障碍记录 |
| 每周 | 交付版本，收集反馈，核对预测 | 一个版本、一份反馈、一条判断修正 |
| 每月 | 复盘项目与系统，整理复用资产 | 一个被整理的资产和一项系统调整 |
| 每季度 | 重选方向、项目和约束 | 完成、终止或升级主项目的明确决定 |

身体系统优先守住睡眠节律、力量与心肺活动、日常活动量和精力高峰时段。精力持续下降时，应先减少项目数量，而不是用意志维持过量承诺。^[inferred]

## Minimal Scorecard

指标只在能够改变决策时保留：

| 维度 | 可观察证据 |
| --- | --- |
| 身体 | 睡眠规律、训练完成情况、主观精力趋势 |
| 注意力 | 主项目深度工作时段、主动中断和切换次数 |
| 主体性 | 自主承诺完成情况、主动放弃的竞争目标 |
| 判断力 | 预测校准、被证据修正的判断、重复误判 |
| 人机协作 | 交付周期、人工验证覆盖、AI 错误沉淀情况 |
| 复利资产 | 模板、工具和知识被再次使用的次数与效果 |
| 真实关系 | 承诺兑现、有效帮助和共同完成的项目 |
| 学习速度 | 从反馈出现到行为或系统修改的时间 |

指标不能替代成果。只记录而不触发决策的指标，应从系统中删除。

## Weekly Review Template

```text
本周要产生的真实结果：
它为谁创造价值：
我亲自负责的关键判断：
交给 AI 的任务：
最重要的假设与预测：
本周交付物：
得到的现实反馈：
哪个判断被修正：
沉淀了什么复利资产：
兑现了对谁的承诺：
下周唯一需要改变的变量：
```

## Failure Modes

- **习惯替代成果**：每天都完成打卡，却没有可被现实检验的交付。
- **记录替代反馈**：复盘越来越详细，但结论不改变下一轮行动。
- **AI 替代判断**：AI 同时定义问题、生成答案并宣布答案正确。
- **多项目稀释注意力**：许多方向都有进展感，没有一个方向获得足够反馈。
- **人脉替代协作**：互动数量增加，却没有共同承担、交付和修正。
- **收藏替代资产**：内容被保存，却不能在后续任务中被调用。
- **指标反客为主**：为了维持数据好看而回避真正困难且重要的问题。
- **透支身体换短期产出**：短期交付增加，长期判断、情绪和恢复能力下降。

## Implications

这套系统的成效不由记录完整度决定，而由现实变化决定：身体是否更稳定，关键判断是否更准，交付是否更快，成果是否被使用，关系是否更可信，过去的劳动是否持续降低未来成本。

系统不要求所有能力同步最大化。它要求主项目不断暴露当前瓶颈，再把有限训练资源投入最限制结果的变量。能力发展因此不是平均加点，而是围绕真实结果进行约束驱动的迭代。^[inferred]
